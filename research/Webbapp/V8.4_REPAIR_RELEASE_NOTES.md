# PRECISION V8.4 REPAIR — FINAL RELEASE NOTES

## Purpose
V8.4 is a surgical repair release based on the supplied PRECISION V8.3 package. Existing application/data/features are preserved; the repair targets the startup path that was producing the `Startup recovery` screen on the deployed V8.3 build.

## Repair changes
- Deterministic deferred script order: `app.js` → `v8-enhancements.js` → `boot-check.js`.
- V8 enhancement boot no longer depends on `DOMContentLoaded`; the enhancement layer boots immediately after the deferred scripts have loaded.
- Enhancement-layer startup is wrapped with a recovery boundary so a runtime exception cannot leave the interface as a silent/blank shell.
- Recovery exposes the captured startup exception and a retry control without clearing stored workspace data.
- Startup watchdog was extended slightly to avoid false recovery during slow mobile startup while retaining a hard recovery path.
- Cache namespace bumped from V8.3 to V8.4 so stale V8.3 service-worker/cache assets cannot be silently reused after redeployment.
- Service-worker registration query bumped to V8.4.
- Release marker updated to V8.4-REPAIR.

## Preserved
- 191 original files remain present before the release-note addition; no original data/application file was removed.
- 1,300 PYQ records and the 2014–2026 corpus remain intact.
- 50 mock-test registry entries remain intact.
- 162 registered features remain intact.
- Study subject/timer system remains intact.
- OMR review → key vault → final evaluation flow remains intact.
- Official answer-key ingestion remains intact.
- D-Day date/time gate remains intact.
- Device passkey implementation remains intact.
- Mistral Small 4 model identifier `mistral-small-2603` remains the default.
- Cloud/local persistence architecture remains intact.

## Verification
The release was checked three times using the included static QA and functional smoke suites, plus JavaScript syntax checks and a file-integrity comparison against the supplied V8.3 ZIP. The only original application files changed are `index.html`, `v8-enhancements.js`, and `sw.js`; the additional file is this release note.

## Deployment note
Deploy this repaired ZIP as a fresh deployment. Because the cache namespace is V8.4, the browser will not intentionally reuse the old V8.3 cache namespace.
